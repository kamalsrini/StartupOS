**StartupOS is the AI-native operating system founders use to build, grow, and manage their startup — not generate it.**

The key architectural insight (from user, 2026-05-27):
> "Use our OS as the place to keep all memory about the startup and then retrieve it to use within different parts like finance and sales etc."

So StartupOS is **a persistent memory layer + module surface**, not just a dashboard. Mission, ICP, brand voice, pricing, team, decisions, customer feedback, financial state — all live in shared memory. Every module (Sales, Finance, Marketing, Build, Commerce) retrieves from that memory to do its work without starting cold.

**Positioning:** "The founder operating system that opens with work already done." Anti-Polsia (phantom completions, hostile reputation), anti-Lev (stops at strategy), anti-Gumloop (blank canvas). Pre-populated, approve-before-execute, MCP-native.

**Modules in scope (per user 2026-05-27):**
1. Sales / Outbound — wedge, powered by UnitOne GTM stack (see [[unitone-gtm-stack]])
2. Company / Mission / Org — cockpit
3. Finance — Stripe, QuickBooks, Mercury integration
4. Marketing / Web / Social — Ahrefs, Klaviyo, content engine
5. Coding / Build — GitHub, Linear, PagerDuty
6. Commerce MCP integrations — Stripe, Shopify, Chargebee

**Audience:** Public product, not personal cockpit. Users + customers will use it. (User clarified 2026-05-27: "post it, users and customers will find it useful outside.")

**Pricing thesis:** $99 Founder / $299 Team / $999 Growth. Flat, not credit-based (Gumloop's #1 complaint). No revenue share (Polsia's 20% is universally hated).

**How to apply:** Every build decision for this project should ask: (a) does this make the memory layer richer? (b) does it open with work already done, not a blank state? (c) does the user approve before the system executes? Pre-built workflows > clever canvases.
